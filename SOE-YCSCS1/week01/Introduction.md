## 2. 언어 구현 방식 비교

### 인터프리터 (Interpreter)

> [!tip] **핵심**
> 실행 전 사전 처리(전처리) 과정이 없는 **온라인(Online)** 방식

* **실행 구조**: 소스 코드 + 데이터 ➔ 인터프리터 ➔ 결과 출력
* **특징**:
  * 코드를 작성하고 실행을 요청하면 그 즉시 동작
  * 별도의 사전 번역이나 컴파일 단계가 없음
* **장단점**:
  * **장점**: 개발 속도가 빠르고 바로 실행해보기 좋음
  * **단점**: 실행 속도가 수동 작성 코드나 컴파일 언어 대비 **10~20배 느림**

---

### 컴파일러 (Compiler)

> [!tip] **핵심**
> 실행 전 미리 번역을 수행하는 **오프라인(Offline)** 방식

* **실행 구조**:
  * **1단계 (컴파일)**: 소스 코드 ➔ 컴파일러 ➔ 실행 파일 (어셈블리/바이트코드 등)
  * **2단계 (실행)**: 실행 파일 + 데이터 ➔ 결과 출력
* **특징**:
  * 소스 코드를 입력받아 실행 파일을 먼저 생성
  * 생성된 실행 파일은 별도로 독립 실행 가능
* **장단점**:
  * **장점**: 재컴파일 없이 동일한 실행 파일로 다양한 데이터셋을 반복 실행 가능
  * **단점**: 실행하기 전에 사전 컴파일 단계가 필요함

---

## 3. 개발 역사 및 배경

### IBM 704 (1950년대)

> [!warning] **당시의 문제점**
> 하드웨어 가격보다 소프트웨어 개발·유지 비용이 훨씬 더 비쌈

* IBM의 첫 상업적 성공작 기계
* 장비 자체가 매우 고가였음에도 소프트웨어 작성 비용이 하드웨어 비용을 훨씬 뛰어넘는 현상 발생
* 프로그래머의 생산성을 높이는 것이 최우선 과제로 부상

### Speed Coding (1953)

* **개발자**: John Backus
* **특징**: 초기 형태의 인터프리터
* **한계**:
  * 개발 생산성은 올라갔으나 실행 속도가 **10~20배 느림**
  * 용량은 **300byte**였지만 당시 IBM 704 전체 메모리의 **30%**를 차지할 정도로 부담이 컸음

### FORTRAN 프로젝트 (1954~1957)

> [!info] **혁신**
> 수식을 실행할 때 해석(Interpret)하지 말고, 기계어로 미리 번역(Compile)해두자!

* **개발자**: John Backus (Formula Translation 프로젝트)
* **경과**: 1년 완성을 예상했으나 실제로는 **3년** 소요
* **성과**:
  * 1958년 기준 전체 프로그램의 **50% 이상**이 포트란으로 작성됨
  * 최초의 성공적인 고수준 언어(High-level language)
  * 컴퓨터 과학 이론과 실무 구현 발전에 큰 영향을 줌

## 4. 컴파일러 5단계 구조 (FORTRAN I 기준)

> [!example] **현대 컴파일러의 기본 틀이 된 5가지 처리 단계**

1. **Lexical Analysis (어휘 분석)**: 구문적(Syntactic) 요소 처리
2. **Parsing (구문 분석)**: 구문적(Syntactic) 구조 파악
3. **Semantic Analysis (의미 분석)**: 타입(Type), 스코프(Scope) 규칙 등 의미론적 검증
4. **Optimization (최적화)**: 실행 속도 향상 및 메모리 절감 변환
5. **Code Generation (코드 생성)**: 기계어, 바이트코드, 타 고수준 언어로 최종 번역
