> 컴파일러의 5가지 주요 단계(Phase) 개요 및 인간의 언어 (영어) 이해 방식과의 비교 분석

---

## 2. 인간의 언어 이해 과정과 컴파일러 단계 비교

컴파일러가 프로그램을 이해하고 번역하는 과정은 인간이 문장을 읽고 이해하는 방식과 매우 유사합니다.

| 인간의 언어 이해 (English)               | 컴파일러 단계 (Compiler Phase)      | 주요 역할                          |
| :-------------------------------- | :---------------------------- | :----------------------------- |
| **단어 구분 (Words)**                 | **Lexical Analysis (어휘 분석)**  | 단어 단위(Token) 분리 및 공백/문장부호 처리   |
| **문장 구조 파악 (Sentence Structure)** | **Parsing (구문 분석)**           | 문법에 맞게 구조화하여 트리(Parse Tree) 생성 |
| **의미 이해 (Meaning)**               | **Semantic Analysis (의미 분석)** | 일관성 검사, 타입 체크, 변수 스코프 확인       |
| **글 교정 및 단순화 (Editing)**          | **Optimization (최적화)**        | 동일한 의미를 유지하며 자원(시간/메모리) 절약     |
| **다른 언어로 번역 (Translation)**       | **Code Generation (코드 생성)**   | 타깃 언어(어셈블리 등)로 최종 번역           |

---

## 3. 컴파일러 5단계 상세 정리

### 1) Lexical Analysis (어휘 분석)

> [!tip] **핵심**: 프로그램 텍스트를 최소 의미 단위인 **토큰(Token)**으로 분리

* **동작 방식**: 공백(Blank), 세미콜론과 같은 구분자/문장부호를 인식하여 단어(Token)를 나눔
* **주요 토큰 종류**:
  * 키워드 (Keywords): `if`, `then`, `else` 등
  * 변수명 (Variables): `X`, `Y`, `Z` 등
  * 상수 (Constants): `1`, `2` 등
  * 연산자 (Operators): `==`, `=` 등
  * 구분자/문장부호: 세미콜론(`;`), 공백(Blank) 등

---

### 2) Parsing (구문 분석)

> [!tip] **핵심**: 토큰들을 문법 구조에 맞게 묶어 **구문 트리(Parse Tree)** 형성

* **영어 문장 비유**: 주어 + 동사 + 목적어로 구성된 문장 구조를 계층적 트리 구조로 표현하는 것과 동일
* **프로그램 적용**:
  * 예: `if-then-else` 문은 조건식(Predicate), `then` 실행문, `else` 실행문의 3개 가지(Branch)를 가진 트리 형태로 구성됨

---

### 3) Semantic Analysis (의미 분석)

> [!warning] **한계와 역할**
> 컴파일러는 프로그램의 '진짜 의도/의미'를 완벽히 이해할 수는 없으며, 주로 **비일관성(Inconsistency) 및 에러 검출**을 수행함

* **영어 문장 비유**: 
  * "Jack said Jerry left his assignment at home" ➔ `his`가 Jack인지 Jerry인지 모호함 (프로그래밍의 **변수 바인딩/스코프** 문제와 유사)
  * "Jack looked her homework" ➔ 남성(Jack)과 여성 대명사(her) 불일치 (프로그래밍의 **타입 검사/Type Checking** 문제와 유사)
* **주요 검사 항목**:
  * 변수 스코프 및 바인딩 (유효 범위 확인)
  * 타입 검사 (Type Checking)

---

### 4) Optimization (최적화)

> [!tip] **핵심**: 프로그램의 의미는 유지하면서 사용하는 **자원(시간, 메모리, 전력, 네트워크 요청 등)을 절감**하도록 코드 변환

* **편집(Editing) 비유**: "a little bit like editing" ➔ "akin to editing" (뜻은 같지만 더 짧은 단어로 교정)
* **주의사항 (최적화의 정당성)**:
  * 예: `X = Y * 0` ➔ `X = 0` 으로 변환
  * **정수(Integer)** 타입에서는 항상 올바른 최적화임
  * **부동소수점(Floating Point / IEEE 754)** 표준에서는 `NaN * 0 = NaN`이므로 `X = 0`으로 바꾸는 최적화가 불가능함 (함부로 최적화하면 잘못된 결과 발생)

---

### 5) Code Generation (코드 생성)

> [!tip] **핵심**: 고수준 언어를 타깃 언어(주로 **어셈블리 코드**)로 최종 번역

* **번역(Translation) 비유**: 영어를 프랑스어로 번역하듯, 고수준 소스 코드를 기계/하드웨어가 이해할 수 있는 어셈블리 코드로 일대일 대응 변환

---

## 4. 컴파일러 구조의 시대적 변화

| 구분 | 초창기 컴파일러 (FORTRAN I 시대) | 현대 컴파일러 (Modern Compiler) |
| :--- | :--- | :--- |
| **Lexical / Parsing** | 비중이 크고 복잡함 | 자동화 도구의 발달로 매우 작고 단순해짐 |
| **Semantic Analysis** | 매우 단순/약함 | 상당히 복잡하고 비중이 커짐 |
| **Optimization** | 적당한 수준 | **전체 컴파일러에서 가장 압도적이고 핵심적인 비중 차지** |
| **Code Generation** | 복잡함 | 원리가 잘 확립되어 상대적으로 비중이 작아짐 |
